# tools

Run from your computer, not the NAS: the ones that read NAS files use the shares
mounted with cifs (mount line: [media re-encoding](../docs/guides/13-media-reencoding.md)).
What runs on the NAS is in [`scripts/`](../scripts/); what maintains this repo, in
[`dev/`](../dev/README.md).

| Script               | Does                                                                                                                                                                                                           |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `duplicates.sh`      | finds identical files inside one folder and deletes the extra copies, keeping one each                                                                                                                         |
| `mikrotik/ntfy.rsc`  | RouterOS 7 scripts pushing to ntfy: a new device on the LAN, internet down/back, WireGuard peers connecting ([guide 11](../docs/guides/11-notifications.md)). Generated by `mikrotik/ntfy-rsc.py`              |
| `mikrotik/deploy.sh` | deploys `ntfy.rsc` to the router and the Wi-Fi AP over SSH, each with its own settings, and checks the result; real values in a gitignored `mikrotik/mikrotik.env`                                             |
| `reencode/`          | shrinks H.264 files to HEVC in place on a desktop Intel GPU, over the `media` share; `reencode-compare.sh` tries the presets on one episode first ([media re-encoding](../docs/guides/13-media-reencoding.md)) |
| `immich-verify/`     | is every photo of a folder or archive (Takeout zips too) already in someone's Immich? Hashes here, sends only hashes, copies out (or uploads) the missing ones. Also: photos in two accounts at once           |

## duplicates.sh

```bash
tools/duplicates.sh "/mnt/homes/<…>/<user>-<…>/Photos"        # shows what it would delete
tools/duplicates.sh -a "/mnt/homes/<…>/<user>-<…>/Photos"     # deletes
```

- One folder at a time, e.g. one person's `Photos`: files elsewhere are never compared.
- Identical means identical content: same size, same first and last bytes, and the same
  BLAKE3 hash of the whole file. Names, dates and folders don't matter; a copy with
  different EXIF data (e.g. an edited photo) is a different file and stays.
- Keeps the most deeply nested copy: the phone backup
  (`MobileBackup/…/DCIM/Camera/2021/10/x.mp4`) rather than a Google Takeout copy
  (`Photos from 2021/x.mp4`). `-k '<pattern>'` protects more paths.
- Skips DSM's `#snapshot`, `#recycle` and `@eaDir` folders, empty files, and `.json` files
  (Google Takeout's per-photo metadata: identical ones can belong to different photos).
  `-m <size>` ignores smaller files.
- Installs a pinned, checksum-verified fclones into `~/.local/share/homelab/` on first run.
  Reports and plans go to `~/duplicates/`.
- **Space comes back** only once the share's recycle bin is emptied and the snapshots
  that still hold the files have expired (`homes`: 14 days, immutable).
- Google Takeout exports keep arriving (every 2 months): run it again after extracting one.

## immich-verify

A static Linux binary, built in a container, Docker or rootless Podman (no Rust needed): `tools/immich-verify/build.sh`,
then `tools/immich-verify/target/release/immich-verify`. Two commands, both on SHA-1, the
checksum Immich keeps for every file:

```bash
# Already in alice's account? A dry check, then copy out what is not.
immich-verify check --server https://immich.home.example.com --person alice ~/Takeout/takeout-*.zip ~/Pictures/Phone
immich-verify check --server https://immich.home.example.com --person alice --extract ~/Takeout/takeout-*.zip

# Copy out what is missing, upload it with immich-go, and check again (--dry-run first).
immich-verify check --server https://immich.home.example.com --person alice --upload --dry-run ~/Takeout
immich-verify check --server https://immich.home.example.com --person alice --upload ~/Takeout

# In anyone's account? Each file is present if any of them has it.
immich-verify check --server https://immich.home.example.com --person alice --person bob ~/Takeout

# Photos in both accounts (the same file uploaded by both).
immich-verify overlap --server https://immich.home.example.com alice bob
```

- **The key:** `--person alice` reads `~/immich-go/token.alice`, the file
  `scripts/immich-import.sh` uses; or `--key-file`, or `IMMICH_API_KEY`. It decides whose
  account is checked. Both repeat: with several accounts a file is `present` when any of
  them has it, `trashed` when only a trash does, `missing` when none does; `report.tsv`'s
  last column says who (`alice,bob`, `bob (trash)`), the stats count each combination, and
  `--extract` copies only what none has, to upload to the first `--person`. `check` needs the `asset.upload` permission, `overlap` `asset.read`
  and `user.read` (a key with all permissions has them).
- **Sources:** folders (an unpacked Takeout too), `.zip` (Google Takeout or any), `.tar`, `.tar.gz`/`.tgz`. Zips are
  read entry by entry, never unpacked; several entries are hashed at once. Hashes are
  cached in `~/.cache/immich-verify/`, so a second run only reads what is new:
  `--offline` hashes without asking Immich, to have it done ahead (by path, size and
  date: a moved or copied source is hashed again).
- **Only hashes go to Immich** (`POST /api/assets/bulk-upload-check`, 1000 per request):
  through Caddy, from the LAN or the VPN. Nothing to run on the NAS.
- **`report.tsv`**, one line per file: `present`, `missing`, `trashed` (only in Immich's
  trash: restore it there), `error`, `empty`, `not-media` (Takeout's `.json`, documents:
  never in Immich) and `ignored` (`@eaDir`, `#recycle`, `.DS_Store`...). Exit code 0 when
  every photo and video is present, 1 otherwise. At the end, the run's numbers: photos and
  videos and how many are copies of another, what was read (and how fast) and what came
  from the cache, what Immich was asked, what was copied out, the time it took.
- **While it runs**, a line per step (listing, hashing, asking Immich, copying) and a
  live count under it: files and bytes done, speed and time left. In a pipe or a log
  (`2>&1 | tee`), that count is a line every 30 s.
- **`--extract`** copies the missing files to `<out>/missing/<source>/`, with their paths,
  and every `.json` from the same folders: Takeout's dates, descriptions and albums. From a folder on the same disk they are hard links: instant, no space used (from an archive, copies). It then
  prints the immich-go commands for that folder (`from-google-photos` for a Takeout,
  `from-folder` for the rest; a Takeout is recognised by its `.json` next to the photos,
  zipped or not), to run from the desktop: no copy to the NAS first.
- **`--upload`** does `--extract`, then runs those commands itself, into the first
  `--person`'s account, as `scripts/immich-import.sh` would: tag `import/<person>/<date>`,
  one failed file does not stop the rest, logs in `<out>/`. Then it asks Immich again:
  `report.tsv` and the stats say what arrived and what is still missing (immich-go skips
  some on purpose: its log says why). `--dry-run` only shows immich-go's counts; immich-go's
  own options go after `--` (`-- --include-unmatched`). immich-go is `$IMMICH_GO`, else on
  the `PATH`, else `~/immich-go/immich-go`. The keys reach it in a config file only you can
  read, removed after, never on the command line. If any `--person` is an Immich admin, its
  key pauses Immich's jobs during the upload; otherwise they keep running.
- **`overlap`** lists both accounts' checksums (`POST /api/search/metadata`) and writes
  `overlap.tsv`: each photo both have, its date, its name and a link to it in each account;
  on screen, each account's size and what share of it the other has too.
  Only what each account owns: a partner's photos shown through Partner Sharing are not
  counted. The trash and the hidden halves of Live Photos are left out.
- **"present" means byte for byte.** A resized or re-saved copy (WhatsApp, Takeout's
  "Storage saver", `-edited`) is `missing`. And present in Immich is not yet backed up:
  before deleting a source, see [guide 12](../docs/guides/12-immich.md#import-existing-photos).
